# GSAP 학습 프로젝트 재설계

## 배경

기존 앱은 실행 결과와 예제 소스를 웹 화면에 함께 표시했다. 이 구조는 데모 면적을 줄이고, `?raw` import와 문법 하이라이터 같은 학습 외 코드까지 만들었다. 모든 레슨 스타일을 한 전역 CSS 파일에 쌓은 결과, 예제 소스와 화면의 초기 상태를 함께 읽기도 어려워졌다.

새 프로젝트는 웹과 에디터의 역할을 분리한다. 웹은 GSAP의 실제 동작을 관찰하고 조작하는 공간이며, 코드는 저장소에서 직접 읽는 학습 자료다.

## 목표

1. GSAP 공식 API와 자주 만나는 상황을 폭넓게 실험한다.
2. 예제 소스를 직접 읽으며 GSAP, React 생명주기, cleanup의 작동 방식을 이해한다.
3. 개별 API에서 조합 패턴, 실무 페이지와 컴포넌트까지 단계적으로 확장한다.
4. CSS는 GSAP 동작에 필요한 초기 상태와 레이아웃을 명확하게 제공하되 학습의 중심이 되지 않는다.
5. 웹 UI는 탐색과 데모 관찰에 필요한 요소만 남겨 학습 집중을 방해하지 않는다.

## 비목표

- 웹 화면에 예제 소스나 코드 하이라이터를 제공하지 않는다.
- 장식만을 위한 애니메이션이나 실무 의미가 없는 복잡한 데모를 만들지 않는다.
- 예제 코드를 설정 객체나 범용 애니메이션 래퍼 뒤로 숨기지 않는다.
- 처음부터 사용처가 불분명한 공통 컴포넌트나 유틸리티를 만들지 않는다.
- CSS 자체를 별도 커리큘럼으로 가르치지 않는다.

## 학습 트랙

### 1. 기본 문법

GSAP 공식 API의 메서드, 옵션, 대표 값 형태를 빠짐없이 다루면서 자주 만나는 상황별 예제도 함께 제공한다.

- 하나의 페이지는 하나의 API나 밀접한 개념을 다룬다.
- 한 페이지 안에서는 `공식 API 항목`과 `상황별 예제`를 구분한다.
- 각 예제는 한 번에 하나의 차이를 관찰할 수 있을 만큼 작게 만든다.
- 같은 옵션이라도 값에 따라 결과가 달라지면 대표 값을 별도 예제로 비교한다.
- 예제 수를 억지로 제한하지 않는다. 대신 중복된 장식이나 학습 차이가 없는 변형은 만들지 않는다.

### 2. 응용 패턴

여러 GSAP 기능을 조합하지만 특정 완성 디자인에는 종속되지 않는 패턴을 정리한다.

- timeline 구성과 재사용
- 연속 입력과 애니메이션 중단 처리
- UI 상태 전환과 cleanup
- 반응형 분기와 reduced motion
- 스크롤, 포인터, 키보드 입력을 결합하는 방식

패턴 페이지는 조합의 목적, 각 기능의 책임, 실패하기 쉬운 지점을 소스 주석으로 설명한다.

### 3. 실무 버전

페이지나 컴포넌트 단위로 실제 제품에 응용할 수 있는 결과물을 만든다.

- 히어로, 내비게이션, 모달, 갤러리 같은 컴포넌트
- 제품 소개, 스크롤 스토리, 페이지 전환 같은 화면 단위 예제
- 반응형, 키보드와 포커스, reduced motion, cleanup, 성능까지 포함

완성도 높은 디자인을 사용하되 시각 효과가 GSAP 학습 목표를 가리지 않게 한다.

## 정보 구조

```text
src/
  app/
    App.tsx
    routes.ts
    app.css
  fundamentals/
    gsap-to/
      GsapToPage.tsx
      examples/
        BasicMovement.tsx
        RelativeValue.tsx
      gsap-to.css
  patterns/
    interruptible-animation/
    responsive-timeline/
  showcases/
    product-hero/
    navigation/
  components/
    learning/
    demo/
  styles/
    global.css
```

- `fundamentals`, `patterns`, `showcases`는 서로 다른 학습 트랙이다.
- 각 트랙은 등록 목록을 통해 제목, 경로, 순서, 그룹을 관리한다.
- 페이지는 route 단위로 lazy loading한다.
- 예제의 GSAP 로직은 해당 예제 파일에 직접 둔다.
- 공통 컴포넌트는 내비게이션, 데모 프레임, 다시 재생처럼 실제 반복이 확인된 UI에만 사용한다.

## 화면 레이아웃

### 상단 트랙 내비게이션

화면 상단에는 `기본`, `패턴`, `실무` 탭을 둔다. 현재 트랙은 URL과 동기화하며, 탭 전환 시 해당 트랙의 마지막 방문 레슨이나 첫 레슨으로 이동한다.

### 고정형 원형 목차

레슨 목차는 항상 펼쳐진 사이드바 대신 필요할 때만 나타나는 원형 버튼으로 제공한다.

- 버튼은 `position: fixed`로 뷰포트 왼쪽 상단에서 일정 간격을 유지한다.
- 데스크톱 지름은 약 40px, 터치 환경은 최소 44px로 한다.
- 상단 트랙 내비게이션과 겹치지 않는 위치에 둔다.
- 버튼을 누르면 현재 트랙의 그룹형 목차가 버튼 아래로 펼쳐진다.
- 목차 항목을 선택하면 해당 레슨 route로 이동하고 자동으로 원형 버튼 상태로 접힌다.
- 열린 상태의 원형 버튼, 바깥 영역, `Escape`로 목차를 닫을 수 있다.
- 목차가 화면 높이를 넘으면 패널 내부만 세로 스크롤한다.
- 현재 레슨을 분명하게 표시한다.
- `aria-expanded`, `aria-controls`, 접근 가능한 버튼 이름을 제공한다.
- 닫힐 때 포커스를 잃지 않으며, route 이동 후에는 새 레슨 제목으로 흐름을 이어갈 수 있게 한다.
- 열림과 닫힘 모션은 짧고 절제하며 reduced motion 설정을 따른다.

### 콘텐츠 영역

- 기본 문법은 가운데 정렬된 단일 열에서 많은 데모를 위에서 아래로 읽는다.
- 예제는 제목, 짧은 설명, 실제 데모, 필요한 조작, 다시 재생 기능으로 구성한다.
- 응용 패턴은 기본 문법보다 넓은 작업 영역을 사용할 수 있다.
- 실무 버전은 해당 페이지나 컴포넌트 디자인에 필요한 전체 폭을 사용할 수 있다.
- 코드 패널과 코드 열기 기능은 제공하지 않는다.

## 소스 코드 원칙

- GSAP 호출과 React 연결 지점이 한 예제 파일에서 바로 보이게 한다.
- import, DOM 참조, GSAP context, tween 또는 timeline 생성, 이벤트 연결, cleanup의 이유를 가까운 위치에 주석으로 설명한다.
- 코드 내용을 그대로 읽는 주석보다 화면과 생명주기에 미치는 영향을 설명한다.
- 예제 간 중복이 있더라도 추상화가 학습 흐름을 숨기면 명시적인 코드를 유지한다.
- 하나의 예제는 하나의 핵심 차이에 집중한다.

## CSS 원칙

- `styles/global.css`는 reset, 디자인 토큰, 문서 기본값만 담당한다.
- `app/app.css`는 상단 탭, 고정형 목차, 공통 콘텐츠 폭 같은 앱 골격만 담당한다.
- 레슨 전용 CSS는 해당 레슨 폴더에 함께 둔다.
- CSS Modules는 사용하지 않는다. TSX에서 실제 클래스 이름과 구조를 바로 읽을 수 있게 한다.
- 레슨별 접두사를 사용해 전역 클래스 충돌을 막는다.
- `opacity`, `transform-origin`, `overflow`, `position`처럼 GSAP 결과에 영향을 주는 초기 상태에는 이유를 주석으로 설명한다.
- 순수 장식 속성에는 불필요한 주석을 달지 않는다.
- 스타일을 공통화할 때는 세 곳 이상에서 동일한 역할이 반복되는지 먼저 확인한다.

## 상태와 데이터 흐름

1. 트랙별 등록 목록이 상단 탭, 원형 목차, route 매칭의 단일 소스가 된다.
2. URL이 현재 트랙과 레슨을 결정한다.
3. route가 바뀌면 이전 예제 컴포넌트가 unmount되며 GSAP context가 cleanup된다.
4. 다시 재생은 데모 영역만 remount하거나 해당 예제가 제공하는 명시적 재생 함수를 실행한다.
5. 인터랙티브 예제의 사용자 상태는 해당 예제 안에만 둔다.

## 오류와 경계 상황

- 존재하지 않는 트랙이나 레슨 경로는 기본 문법 첫 레슨 또는 명확한 찾을 수 없음 화면으로 연결한다.
- 플러그인이 필요한 예제는 파일 안에서 등록 지점을 명확히 표시한다.
- 긴 목차는 화면 전체를 밀어내지 않고 자체 스크롤한다.
- 작은 화면에서도 원형 버튼과 목차가 콘텐츠 및 상단 탭을 가리지 않게 위치를 조정한다.
- 사용자가 빠르게 레슨을 전환해도 이전 tween, timeline, listener가 남지 않게 cleanup한다.

## 기존 프로젝트 초기화

새 구조로 넘어갈 때 기존 학습 페이지를 보존하거나 숨기지 않고 제거한다.

- 기존 `lessons`, 학습 UI 컴포넌트, route 구현, 레슨 전용 전역 CSS를 제거한다.
- `CodeBlock`, 모든 `?raw` import, `prism-react-renderer`와 관련 스타일을 제거한다.
- 기존 검사 스크립트 중 새 구조를 전제로 하지 않는 것은 제거한다.
- Vite, React, TypeScript, GSAP, `@gsap/react`와 기본 실행 설정은 유지한다.
- `project-plan.md`와 `progress.md`는 새 목표와 진행 상태에 맞게 다시 작성한다.
- 기존 `practice-plan.md`는 새 `실무 버전` 트랙 계획에 흡수하고 중복 문서는 제거한다.

## 첫 구현 마일스톤

첫 구현은 전체 커리큘럼을 한꺼번에 채우지 않고 새 구조의 수직 슬라이스를 검증한다.

1. 기존 앱을 최소 Vite + React + GSAP 골격으로 초기화한다.
2. 상단 트랙 탭과 고정형 원형 목차를 구현한다.
3. 기본 문법의 첫 `gsap.to()` 페이지를 새 파일·주석·CSS 규칙으로 작성한다.
4. 여러 개의 작고 구분되는 예제를 통해 다시 재생과 cleanup을 검증한다.
5. 새 문서와 진행 현황을 실제 구현 상태에 맞춘다.

## 검증 기준

- `npm run build`가 성공한다.
- 웹 화면에 소스 코드나 코드 패널이 나타나지 않는다.
- 저장소의 실행 코드에서 `?raw`, `CodeBlock`, `prism-react-renderer` 참조가 남지 않는다.
- 세 트랙 탭과 원형 목차가 키보드와 포인터로 동작한다.
- 목차는 선택, 바깥 클릭, `Escape`로 닫히며 접근성 상태가 실제 열림 상태와 일치한다.
- 레슨을 바꾸거나 다시 재생할 때 이전 GSAP 인스턴스와 이벤트가 정리된다.
- 모바일 너비에서 트랙 탭, 원형 버튼, 목차, 데모가 겹치거나 잘리지 않는다.
- 기본 문법 예제 소스만 읽어도 GSAP 호출과 React cleanup 흐름을 이해할 수 있다.
