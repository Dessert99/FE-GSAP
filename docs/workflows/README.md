# GSAP 공식 문서 학습 페이지 제작 workflow

이 workflow는 특정 작업의 진행표가 아니라 GSAP 공식 문서 기반 페이지와 예제를 만들거나 고칠 때마다 반복하는 지속 규칙이다.

세부 계약:

- [공식 내용 coverage](./source-coverage.md)
- [학습형 재구성](./learning-design.md)
- [페이지 형식](./page-format.md)
- [컨텍스트 handoff](./context-handoff.md)
- [품질 게이트](./quality-gates.md)

**작업 단위는 학습 페이지 하나다.** 페이지 하나의 handoff·구현·검증·release를 끝내고 한 커밋으로 남긴 뒤 다음 페이지로 넘어간다.

1. **공식 문서 읽기** — 공식 URL과 제목, 대조일, 모든 기술 내용, 시그니처·반환값, 전제 지식·의존성을 source manifest로 고정한다.
2. **페이지 분류** — [선택형 페이지 모듈](./page-format.md#선택형-페이지-모듈) 중 필요한 유형을 고른다. 한 페이지가 여러 유형을 결합할 수 있다.
3. **coverage 작성** — 모든 기술 항목을 로컬 명세, 섹션, 예제, warning에 연결한다. 비기술 영역 외에는 제외하지 않는다.
4. **학습 흐름 설계** — 공식 내용을 그대로 번역하지 않고 초보자의 질문과 관찰 순서에 맞게 재구성한다.
5. **handoff 고정** — 다른 컨텍스트도 같은 결과를 만들 수 있도록 source, coverage, 파일, 검증 필드를 고정한다.
6. **구현** — 페이지 성격에 맞는 실행 source를 선택하고 실행 config와 표시 코드를 같은 runtime state에서 파생한다.
7. **자기 검증** — 전체 coverage, 학습형 재구성, 필요한 실행·구조·접근성·통합을 관점마다 따로 판정한다. 공식 문서가 침묵하는 동작은 runtime probe로 확인한다.
8. **수정** — `BLOCK`을 고치고 영향받은 관점을 다시 판정한다. 새 문제나 미해결 문제가 없을 때까지 반복한다.
9. **release 판정** — 두 핵심 조건과 검증 증거를 대조해 release 여부를 기록한다.

자동화 테스트 코드와 테스트 실행 환경은 추가하지 않는다.
