# 학습형 재구성 계약

공식 내용을 정확성의 source로 사용하되 공식 문장과 목차를 그대로 복제하지 않는다.

## 기술 item 재구성

각 item에서 학습에 필요한 항목을 선택한다.

1. 무엇인지
2. 왜 필요한지
3. 먼저 알아야 할 개념
4. 가장 단순한 상태나 동작
5. 값을 바꾸면 달라지는 부분
6. 그렇게 동작하는 이유와 계산 시점
7. 다른 옵션·개념과의 관계
8. 실제 사용처
9. 흔한 오해, 경계, 주의점

모든 item에 같은 UI를 강제하지 않는다. 인터랙션, 단계형 타임라인, 다이어그램, 표, 정적 코드 중 이해에 가장 직접적인 표현을 고른다.

## 예제 계약

- 처음 등장하는 용어를 실행 전에 정의한다.
- 예제가 답할 핵심 질문을 하나로 제한한다.
- 조작할 값과 관찰할 변화를 실행 전에 알려준다.
- 결과뿐 아니라 왜 그렇게 되는지와 실제 사용처를 설명한다.
- 여러 대상이나 상태는 개념 자체일 때만 함께 보여준다.
- 표시 코드와 실제 실행은 동일한 runtime config나 descriptor에서 파생한다.

## 실패 판정

공식 문장의 번역·요약만 있거나, 전제 지식·관찰점·원리 없이 코드만 나열하거나, UI가 있어도 무엇을 봐야 하는지 설명하지 않으면 Learning Transformation을 `BLOCK`한다.
